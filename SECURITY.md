# Security policy

## Reporting a vulnerability

Please report security problems **privately** through
[GitHub security advisories](https://github.com/timruttedev/second-brain-blueprint/security/advisories/new)
("Report a vulnerability"), not in a public issue. Examples: a script that
can be tricked into writing outside the repository, a workflow that leaks
repository content to an external service, or a rule that makes agents
store secrets.

You will get a reply in the advisory, and the fix is credited to you
unless you prefer otherwise.

## Protect your own data

A Second Brain holds your health, money, family and work. When you report
anything about this blueprint, publicly or privately:

- **Never paste content from your own Second Brain** into an issue, a pull
  request or an advisory. Reproduce the problem with the fictional files in
  [`examples/`](examples/README.md) or with made-up text.
- Remove names, paths, file contents and log lines that identify you or
  others before you share output.
- If you accidentally published personal data in an issue, edit or delete
  it right away; GitHub keeps edit history, so contact GitHub support to
  purge it if needed.

## Supported versions

Only the latest release and the `main` branch receive fixes.
